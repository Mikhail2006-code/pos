# ПОС — Преподавательская Оценка Студентов

ДЗ №2 по КПО. Консольное приложение для учёта оценок студентов: DDD, архитектура Ports and Adapters и паттерны GoF.

## Как запустить

Нужен .NET 9. Всё запускается из папки, где лежит `Pos.sln`:

```bash
dotnet run --project Pos.ConsoleApp
dotnet test
```

В меню пункт выбирается цифрой, `0` — выход. Дробные числа можно писать и через запятую, и через точку. Экспорт сохраняет файл `final-grades.csv` в папку, откуда запущена программа.

Сквозной сценарий из условия: добавить студентов (1) и критерии (3) → выставить оценки (5) → посмотреть итог (8) → выгрузить итоги (9).

## Архитектура

Выбрал Ports and Adapters. Каждый слой сделал отдельным проектом, чтобы зависимости внутрь проверял компилятор: если домен вдруг попробует обратиться к консоли или CSV, проект просто не соберётся.

```
Pos.ConsoleApp  ──►  Pos.Infrastructure  ──►  Pos.Application  ──►  Pos.Domain
```

| Проект | Что там лежит |
|---|---|
| `Pos.Domain` | модель: сущности, балл, правила, интерфейсы репозиториев, подсчёт итога |
| `Pos.Application` | фасад со сценариями и интерфейс экспорта |
| `Pos.Infrastructure` | реализации: хранение в памяти и выгрузка в CSV |
| `Pos.ConsoleApp` | меню и сборка всех зависимостей (`CompositionRoot`) |
| `Pos.Tests` | тесты |

Домен ни на кого не ссылается. Порты (`IStudentRepository`, `IRubricRepository`, `IEvaluationRepository`, `IGradeExporter`) лежат внутри, а их реализации (`InMemory…Repository`, `CsvGradeExporter`) — снаружи. Всё связывается через DI-контейнер в `Pos.ConsoleApp/CompositionRoot.cs`.

## DDD

**Словарь.** Названия в коде такие же, как в предметной области:

| Термин | Класс |
|---|---|
| студент | `Student` |
| критерий | `Criterion` (название, максимум, вес) |
| рубрикатор | `Rubric` |
| балл | `Score` |
| оценка | `Evaluation` (студент, критерий, балл, дата, комментарий) |
| итог | считает `FinalGradeCalculator` |

**Entity и Value Object.** `Student`, `Criterion` и `Evaluation` — сущности: у каждой есть `Id`, и два студента с одинаковым именем всё равно разные. `Score` — Value Object: у балла нет своей «личности», семёрка равна семёрке. Сделал его через `record`, поэтому он сравнивается по значению и не меняется после создания.

**Агрегат.** `Rubric` — главный объект для критериев. Добавить критерий можно только через `Rubric.AddCriterion`, и он не даёт завести два критерия с одинаковым названием.

**Правила (инварианты):**

| Правило | Где проверяется |
|---|---|
| балл не меньше нуля | конструктор `Score` |
| максимум и вес критерия больше нуля | конструктор `Criterion` |
| балл не больше максимума критерия | `Criterion.Allows` (вызывает фабрика) |
| оценка только по критерию из рубрикатора | `Rubric.GetCriterion` (вызывает фабрика) |
| названия критериев не повторяются | `Rubric.AddCriterion` |
| итог соответствует текущим оценкам | калькулятор каждый раз считает по всем критериям рубрикатора, если оценки нет — берётся 0 |

Если правило нарушено, летит `DomainException`, и меню показывает её текст. Конструктор `Evaluation` сделан `internal`, так что оценку нельзя создать мимо фабрики.

**Репозитории.** Интерфейсы в домене, реализации в инфраструктуре. Если выставить оценку ещё раз по тому же критерию, старая заменяется — так работает исправление. Отмена удаляет оценку.

**Доменный сервис.** `FinalGradeCalculator` — потому что для итога нужны и рубрикатор, и оценки, и это не относится ни к одной сущности. Итог по 10-балльной шкале:

$$
\text{итог} = 10 \cdot \frac{\sum_i w_i \cdot \dfrac{s_i}{m_i}}{\sum_i w_i},
$$

где $s_i$ — балл по критерию, $m_i$ — его максимум, $w_i$ — вес.

## Паттерны

| Группа | Паттерн | Где | Зачем |
|---|---|---|---|
| порождающий | Фабрика | `EvaluationFactory` | все проверки при создании оценки в одном месте, обойти их нельзя |
| структурный | Фасад | `PosFacade` | меню общается с одним объектом и не знает про репозитории и калькулятор, сценарии не расползаются по UI |
| поведенческий | Стратегия | `IGradingStrategy`: `WeightedGradingStrategy`, `SimpleAverageGradingStrategy` | правило итога можно поменять без правки калькулятора, одной строкой в `CompositionRoot` |

Стратегия не для галочки: в тестах на одних и тех же оценках взвешенное среднее даёт 8,67, а простое — 9.

## Тесты

9 тестов на xUnit:
- `DomainTests` — правила: отрицательный балл, нулевой максимум, повтор названия критерия, балл больше максимума, критерий не из рубрикатора;
- `FinalGradeCalculatorTests` — итог обеими стратегиями, критерий без оценки, пустой рубрикатор.
